## Rulings
- Ruling A: `addTrack` default index: video -> index of the LAST video track + 1 (i.e. directly above existing video layers in compositing order); audio -> end of the array. Cost if wrong: new tracks appear in a different stacking slot (cosmetic).
- Ruling B: `moveTrack(p, id, toIndex)` accepts any index (clamped). UI `moveLayer(id,'up'|'down')` swaps with the neighbouring track OF THE SAME KIND: for video, 'up' = higher array index (higher layer, shown higher); for audio, 'up' = lower array index (shown higher). Cost if wrong: arrows invert (easy swap).
- Ruling C: split T5 into 5a (pure trackLayout + trackCommands + TrackHeader + header controls + Timeline ordering + flags/lock UX + e2e) and 5b (new-layer zone, media/clip drop creating a layer, vertical scroll, remove-confirm flow, e2e) and T6 into 6a (pure overlayGeometry + setClipTransform + TransformFields inspector + unit tests) and 6b (TransformOverlay + useTransformDrag + Preview wiring + pip e2e), for reviewability. Cost: none.
- Ruling D: `dragScale` scales uniformly about the CLIP CENTRE: new scale = start.scale * |pointer - centre| / |startHandlePoint - centre| (clamped 0.02..20); the plan's "opposite corner" wording is dropped. Cost: scale gesture pivots about centre not the opposite corner (matches common PiP tools).
- Ruling E: `clipCorners` and all overlay geometry use FORMAT-PIXEL space with origin at the canvas top-left, y down (canvas centre = (w/2,h/2)); Transform.x/y stay offsets from the canvas centre (as in clipMatrix); the overlay converts CSS pixels -> format pixels with the displayed canvas box. Cost: none.
