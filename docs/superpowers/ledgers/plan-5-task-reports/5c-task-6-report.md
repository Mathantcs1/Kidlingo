# Plan 5C Task 6 (audio crossfade through the shared chain)
- New `audio/crossfade.ts` (`crossfadeInfo`, `crossfadeEnvelopes`, `audibleSpanOf`): for every VALID transition whose two clips can both sound, the outgoing clip plays `d/2` past its end, the incoming `d/2` before its start; envelopes are 33 breakpoints per side (equal power cos/sin of the eased progress, or constant gain 1-e / e), exact 0/1 at the ends.
- `plan.ts`: `planWindow(..., xfades)` extends the span; `Segment.xfade` only when a clip has one (plan without transitions is deep-equal). Plain clips: source time via `sourceTimeAt` past in/out; retimed clips (5D virtual source): virtual time < 0 or > D. `retimeMath.audioSpan/footageToDecode` take the crossfade (decode clamps lifted to the media on that side); `segmentSource` passes it (WSOLA chain start clamps to the extended span).
- `fade.ts clipGainPoints`: fades x crossfade; the clip's own fade on a crossfaded edge is replaced (stored value kept). `chain.ts`: gain automation through `clipGainPoints`, tail-gate closes at `clipEnd + after`. `duck.ts`: the duck interval of a source clip includes its handles. Live (`mixer.ts`) and export (`mixdown.ts`) both build `xfades` once per session/render.
- Deviation: no separate `xfade` GainNode: the crossfade is folded into the existing clip-gain automation (same behaviour, one fewer node).
- Pre-existing live bug found and fixed: `mixer.schedule` ended a node at `when + duration` carrying float error; a window cut inside a crossfade double-counted the cut sample (0.079 at one sample). The node now ends on the planned frame (a hair before it).
