# ClipForge Plan 4: Visual Effects and Looks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the user stack WebGL2 effects on any picture clip (colour, looks, `.cube` LUTs, blur/sharpen/glow/pixelate, stylise, chroma key) and add generated overlays (lower thirds, subscribe button, progress bar, stickers), with a live preview that matches the exported MP4.

**Architecture:** Project data moves to v4 (`Clip.fx`, a new `overlay` clip kind, `Project.luts`). A DOM-free effect schema (`src/fx/`) is shared by core edits and the UI; the renderer side (`src/render/fx/`) turns each effect into one or more shader passes run on an offscreen target per clip, then the existing compositor draws that target with the clip's transform. Preview and export call the SAME `Compositor.renderFrame`, so they cannot drift (same idea as Plan 3's `chain.ts`). Every per-pixel effect has a pure CPU reference formula (`src/fx/reference.ts`) used by Vitest and compared with GPU pixels in Playwright. `compositor.ts` and `gl.ts` are split first, proven pixel-identical by golden images.

**Tech Stack:** WebGL2 (framebuffers, `TEXTURE_3D` for LUTs), Canvas2D/OffscreenCanvas for overlay rasterising, OPFS (LUT files), idb-keyval (unchanged), Vitest, Playwright with real pixel and ffmpeg frame checks. No new runtime dependency (see E8, E9).

**Spec:** `docs/superpowers/specs/2026-11-10-clipforge-design.md` (Effects, lines 35-48; `effects/` and `render/compositor` lines 62-63; test line 84). Roadmap: `docs/superpowers/plans/2026-11-10-clipforge-plan-2-layers.md`. State, rulings, pitfalls: `PROJECT_HANDOFF.md`, `CLAUDE.md`, `docs/superpowers/ledgers/plan-3-audio-ledger.md` (read it for the chain/preview=export rulings this plan copies).

## Decisions to approve (rulings proposed; change any before execution)

- **E1 One pipeline.** `Compositor.renderFrame(p, t, sources)` stays the only draw entry for preview and export; effects live inside it. The exporter and `previewRenderer` need no effect code. Cost if wrong: none user-visible; it is the guard against preview≠export.
- **E2 Effects run in clip space, before the transform** (like CSS filters / Premiere effects). Each clip with effects is drawn upright into an offscreen target of `ceil(displayedSize × clip.scale × canvasPx/formatPx)` per side, never larger than the source nor 4096, at least 8. Pixel-unit params (blur radius, pixelate block, grain size, glitch band height) are in SOURCE pixels of the displayed clip and rescaled by `targetWidth / sourceWidth`, so a PiP clip shrunk to 25 % has a proportionally smaller blur, and a 640 px preview and a 4K export look alike (resampling differences only). Cost if wrong: a user who wants "10 px on screen" gets scaled values; switching the unit later is a schema-only change.
- **E3 Fast path.** No enabled effects ⇒ identical draw calls to Plan 3 (guarded by golden images). All effect machinery is lazily created on first use (compile cost and GPU memory only when used).
- **E4 Data v4:** `Clip.fx: VisualEffect[]` on every clip (audio clips keep `[]`), `Clip.kind` gains `'overlay'` with `Clip.overlay: OverlaySpec` and `mediaId: ''`, `Project.luts: Record<Id, LutRef>`. Params are numbers only: colour = packed `0xRRGGBB`, select = option index, bool = 0/1; a LUT effect stores its library id in `ref`. Plan 5 keyframes can address any numeric param without another migration of this field. Cost if wrong: a v5 follow-up; `Project.version` handles it.
- **E5 Colour math** is done on 8-bit sRGB-encoded, UNPREMULTIPLIED values (the pipeline un/re-premultiplies around every colour effect), except exposure which converts to linear light and back. Intermediate targets are RGBA8 (runs everywhere incl. SwiftShader). Cost: banding under extreme grades; RGBA16F behind a capability check is a later swap inside `TargetPool`.
- **E6 Deterministic time.** Time-driven effects (grain, glitch, VHS) take `clipTime = t − clip.start` and `frame = floor(clipTime × fps)`; the seed is a hash of `(frame, clip.id)`. Rendering the same frame twice gives identical bytes; export frame n equals preview at `t = n/fps`. Cost if wrong: none.
- **E7 Looks are ONE effect:** `type:'look'` with params `preset` (select) and `intensity` (0..1), driven by a data table (`src/fx/looks.ts`: lift/gamma/gain tint, saturation, contrast, fade, vignette, grain) interpolated toward neutral by intensity, single shader pass. Presets: Cinematic, Moody, Golden Hour, Teal-Orange, Fashion, Clean Vlog, Film 35mm, Cyberpunk, Dreamy. A separate `lut` effect (`ref` + `intensity`) covers imported `.cube` files. User-saved looks and "apply look to all clips" are deferred (E12); Copy/Paste effect stack is in.
- **E8 LUTs:** `.cube` 3D only (1D, `LUT_1D_SIZE`, size > 65 or > 20 MB are refused with a plain message; `DOMAIN_MIN/MAX` honoured). The original text is kept in OPFS (`luts/<id>.cube`), registered in `Project.luts`, parsed lazily into an 8-bit `TEXTURE_3D` shared by all clips. `removeLut` refuses while any clip references it; files are deleted only by the verified-restore GC over ids referenced by ANY history state. Missing file ⇒ the effect is skipped, the row shows "LUT missing", nothing else breaks. Cost if wrong: LUTs in IndexedDB would avoid GC changes but bloat autosave.
- **E9 Overlays are clips** (`kind:'overlay'`) on normal video tracks, so move/trim/split/hide/lock/transform/effects/undo/PiP overlay all work unchanged. They are rasterised by Canvas2D into a texture (system font stack, built-in vector stickers, no emoji/fonts bundled, text length-capped), cached in a small LRU, and drawn like an image clip. The progress bar is time-driven (fill = clip-local or whole-project progress). Animated entrances/keyframes are Plan 5. A user PNG already works as a custom sticker (image clip).
- **E10 "Effects off" compare toggle** is a preview-only view flag (`renderFrame` option, never persisted, never used by the exporter).
- **E11 Limits and failure isolation:** at most 12 effects per clip (UI refuses the 13th with a toast); an effect whose shader fails to compile on this GPU is skipped (the rest of the stack renders) with ONE toast naming it; target pool and raster cache are bounded (tests read `stats()`).
- **E12 Not in Plan 4:** keyframed effect params, animated overlays, text clips and transitions (Plan 5); track-level/adjustment-layer effects (per clip only, mirroring Plan 3 D6); user-saved looks; light leaks, lens flares, anamorphic streaks, halation, gate weave, camera shake, zoom punch, letterbox bars, bokeh and animated GIF stickers (spec "premium extras", listed in the ledger for a later plan); 1D LUTs. Chroma key is keyed colour + tolerance + softness + spill (no matte tools).
- **E13 Merge-all** bakes effects and overlays into the merged clip (it renders the composite through this same compositor, so it needs no new code; a test pins it). Detach/Attach, audio and reframe are unaffected (effects are source-space; overlay placement uses the existing reframe rules).

## Review Focus

1. **No-effects parity:** golden images captured BEFORE the split must still match after every task (Tasks 1-12); a project with only disabled effects equals no effects exactly.
2. **Preview = export:** same frame from `renderPixels` and an ffmpeg-extracted exported frame agree (mean abs diff ≤ 4/255) for a stack with colour + look + blur + overlay; time-driven effects are byte-identical on a repeat render.
3. **Alpha and premultiplication:** semi-transparent PNG through every effect: no dark/bright fringes (every colour channel ≤ alpha), alpha preserved except where an effect defines it (chroma, mirror edges); opacity < 1 on an effected clip; blurred-fit (`fit:'blur'`) background uses the processed picture.
4. **GL lifetime:** pooled targets/textures bounded after 100 frames, resize, hide/unhide, context loss mid-render, `dispose()` twice, compile failure of one effect (stub via `gl-stub.ts`), 6 layers × 3 effects.
5. **Odd inputs:** portrait/rotated/mirrored phone video (effects see the upright displayed picture: mirror direction and vignette must not rotate with the file), 4K frame, scale 0.02 clip (8 px target), huge blur radius, NaN/out-of-range params from a hand-edited save (repaired per field), clip with every effect disabled, audio clip (refused), hidden/locked tracks.
6. **Data safety:** v3→v4 with clips on every track kind and a v3 audio-effect project; a v4 save opened by this build; `{version:5}` stays protected; malformed `fx`/`overlay`/`luts` repaired per field, never rejecting the project; LUT ids survive undo and are only GC-deleted when no history state references them; "New project" and media removal never delete a referenced LUT.
7. **Overlay robustness:** empty text, very long text, unusual scripts (rendered with the system fallback, no crash), 1-frame overlay, overlay at 0.02 scale, format switch (reframe round trip), raster cache bounded, progress at 0 %/100 %.

### Task 4: Render pipeline and colour effects
