What you get

  • A 43-line MCP server in Python (official SDK 2.x, MCPServer)
  • A sample store database: 40 customers, 8 products, 500 orders (generated, not real data)
  • A plain-SQL check script, so you can verify every number the AI gives you
  • A raw JSON-RPC script, so you can see what an AI app actually sends

Run it in five steps

  1. Unzip the kit and run bash setup.sh (creates a virtual environment, installs mcp 2.3.0, builds shop.db). It uses uv, so install that first if you do not have it.
  2. Run .venv/bin/python truth.py to see the ground truth: October 2026 revenue 18,764.70; top product 27in Monitor (5,229.00); top city Boston (4,469.46); 40 cancelled orders.
  3. Run .venv/bin/python raw_client.py to watch the raw handshake and one tool call (count orders: 500).
  4. Connect it to Claude Code: claude mcp add store -s project -- .venv/bin/python server.py, then run claude and approve the new server.
  5. Ask: “Which product earned the most revenue from delivered orders in October 2026?” Compare the answer with truth.py.

The whole server

import sqlite3
from mcp.server import MCPServer

mcp = MCPServer("store")

# Safety layer 2: the connection itself is read-only, so even a bad query cannot change data.
def db() -> sqlite3.Connection:
    """Open shop.db in read-only mode."""
    return sqlite3.connect("file:shop.db?mode=ro", uri=True)

@mcp.tool()
def list_tables() -> str:
    """List the tables in the store database."""
    with db() as c:
        return "\n".join(r[0] for r in c.execute("select name from sqlite_master where type='table'"))

@mcp.tool()
def describe_table(table: str) -> str:
    """Show the columns of one table. Call this before writing SQL."""
    with db() as c:
        return "\n".join(f"{n} {t}" for n, t in c.execute("select name, type from pragma_table_info(?)", (table,)))

@mcp.tool()
def run_sql(query: str) -> str:
    """Run one read-only SQL SELECT query and return the rows."""
    if not query.strip().lower().startswith("select"):  # Safety layer 1: only SELECT gets through
        return "Blocked: this server only allows SELECT queries."
    with db() as c:
        return "\n".join(" | ".join(map(str, row)) for row in c.execute(query))

# A resource is data to read; a prompt is a ready-made template.
@mcp.resource("store://about")
def about() -> str:
    """What is in this database."""
    return "A sample online store: customers, products and orders. Orders have no price column."

@mcp.prompt()
def monthly_report(month: str) -> str:
    """A ready-made request for a monthly sales report."""
    return f"Give me the {month} sales report: total revenue, top product and top city, delivered orders only."

if __name__ == "__main__":
    mcp.run()

Two safety layers

  1. Server code: run_sql refuses anything that does not start with SELECT.
  2. Database connection: shop.db is opened read-only (mode=ro), so even a bad query cannot change data.

Try it: ask the AI to delete the cancelled orders. The server answers “Blocked: this server only allows SELECT queries”, and a direct delete fails with “attempt to write a readonly database”. The 40 cancelled orders stay.

Things to know

  • Python SDK 2.x uses from mcp.server import MCPServer. Many tutorials still use FastMCP, which no longer imports on current versions.
  • MCP itself does not enforce security. The specification asks hosts to get explicit user consent, but your server’s guardrails are your job.
  • The AI’s wording changes from run to run. The numbers come from SQL and should always match truth.py.
  • Everything uses sample data. Review any MCP server before pointing it at real data.
