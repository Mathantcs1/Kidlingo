Why can a chatbot write a whole essay and still miscount the letters in a word? Because it never sees single letters the way you do. It reads and writes text in chunks called tokens.

Once you know that, several odd habits of chatbots start to make sense.

Text in chunks

Before a language model reads anything, a small program called a [ita_term define="The program that splits text into tokens and turns each token into a number before a model reads it."]tokenizer[/ita_term] splits the text into pieces. Each piece is a [ita_term define="A small piece of text, often a whole short word or part of a longer one, that a language model reads and writes."]token[/ita_term]. Each token then becomes a number, and the model works with those numbers.

Common short words are often one token each. Longer or rarer words are often split into several. Spaces and punctuation are part of tokens too.

[ita_figure name="token-splitting" alt="The sentence Learning AI is fun, with a period, is split into six chunks: Learn, ing, AI, is, fun and the period." caption="Learn and ing are two chunks, so the letters inside them are not separate. Example only."]

Look at "Learning" in the picture. The model gets two chunks, "Learn" and "ing". It doesn't get L, e, a, r, n, i, n, g. To know which letters are inside a chunk, it has to rely on what it learned in training.

Four things tokens explain

1. Spelling and letter puzzles

Ask how many times the letter "e" appears in "bookkeeper", and a chatbot can get it wrong. The letters are hidden inside chunks. Newer apps get this right more often, sometimes by writing the word out letter by letter first. You can ask for that yourself:

[ita_prompt title="Spell it out first"] Write the word [word] one letter at a time, with a space between letters. Number each letter. Then count how many times the letter [letter] appears, and show your count. [/ita_prompt]

Writing the letters out turns each letter into its own token, so the count no longer depends on what's hidden inside a chunk. This [ita_term define="The message or instructions you type to an AI app to tell it what you want."]prompt[/ita_term] trick works for other small puzzles too, such as rhymes or reversing a word.

2. Answers that stop early

Apps and models measure length in tokens, not words. An answer has a limit on how many tokens it can use. When it reaches that limit, the answer can stop in the middle of a sentence. Asking it to continue usually works.

3. Other languages and writing systems

Tokenizers are built from large amounts of text, and English is very common in that text. The same meaning written in some other languages or writing systems can take more tokens. That text reaches length limits sooner.

4. Long numbers and rare names

A long number such as 4,817,206 may be split into uneven chunks. That's one reason doing arithmetic "in its head" can go wrong. For sums that matter, use a calculator, or an app that can run a calculation for you.

For builders: counting tokens

If you send requests to a model from your own code, tokens are your unit of measure. Every request has input tokens (everything you send) and output tokens (the reply). Each model has limits on both, and services that charge by usage usually count tokens.

  • Most model APIs report the tokens a request used in the response. Log those numbers from the start.
  • Different models split text differently. A count from one model's tokenizer may not match another's.
  • Formatting uses tokens too. Long JSON keys, indentation and repeated instructions all add to the count.
  • Count before you send, if your provider offers a counting function, so a request doesn't fail for being too long.
[ita_why title="Why not use single letters, or whole words?"]

Single letters would make every text very long. The model would need many more steps to read and write the same sentence, and less text would fit in at once.

Whole words have the opposite problem. There are too many of them, and new words, names and typos appear all the time. A word-only system would have no way to handle a word it had never seen.

Chunks are a middle path. Tokenizers learn their chunks from large amounts of text, keeping frequent pieces whole and splitting rare ones. Any new word can still be built from smaller chunks.

Try it

A two-minute look at chunks.

  1. Ask any chatbot how many times the letter "s" appears in "Mississippi". Note its answer.
  2. In a new chat, send the "Spell it out first" prompt with the same word and letter.
  3. Count the letters yourself on paper.
  4. If you build with a model API, put one sentence and its translation into your provider's token counter. Note both counts in your project notes.
