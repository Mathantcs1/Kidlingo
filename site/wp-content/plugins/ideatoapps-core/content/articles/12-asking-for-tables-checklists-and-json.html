Ask a chatbot for "a table of this week's stock count" and you'll get a table. The columns and their order, though, are the chatbot's choice. They may not match the sheet you already use.

Name the columns, the order and what to write when a value is missing, and the result fits where it's going.

Tables: you choose the columns

Say you run a small hardware store and your staff write stock counts on paper. A [ita_term define="The message or instructions you type to an AI app to tell it what you want."]prompt[/ita_term] like this turns their notes into rows you can use:

[ita_prompt title="A table with fixed columns"] Make a table from the stock count notes below. Columns, in this order: Item, Shelf, Count, Reorder. Reorder is "yes" when the count is below [your reorder level], otherwise "no". One row per item, sorted by shelf. If a note does not give a value, write "missing" in that cell. Do not guess a value. Notes: [paste the notes here] [/ita_prompt]

The last two lines do a lot of work. Without them, a chatbot may fill an empty cell with a likely-looking number. A "missing" cell is easy to spot and fix. A made-up count is not.

Tables in a chat window can lose their layout when you paste them into a spreadsheet. If that happens, ask for the same table as [ita_term define="Comma-separated values: plain text where each line is a row and commas separate the cells. Spreadsheets can open it."]CSV[/ita_term] instead. It often pastes more cleanly.

Checklists: one action per line

A paragraph of instructions is hard to follow at the end of a long shift. A checklist is easier. To get a good one, say how it will be used:

  • Start each line with a verb, such as "turn off", "wipe" or "lock".
  • One action per line, so each line can be ticked on its own.
  • Group by place or time, for example "grill area", "counter", "last five minutes".
  • Say where it will live: printed on a wall, read on a phone, or pasted into a shared document.

Imagine a food truck's closing checklist. "Clean up the grill area properly" becomes three lines a new worker can follow: scrape the grill, empty the grease tray, wipe the hood filters. If the chatbot's version merges steps, ask it to split any line that has two verbs.

JSON: when a program reads the answer

[ita_term define="A plain-text format for data, made of named fields and values inside curly braces, that most programs can read."]JSON[/ita_term] is for answers that a program will use, for example to fill a form or save an order. For builders, the safest request shows the exact shape you expect:

[ita_prompt title="Fixed keys for an order message"] Read the customer message below and return only JSON, with no text before or after it. Use exactly these keys, in this shape: {"product": "flyers", "quantity": 200, "paper": "glossy", "deadline": "2026-12-01", "questions": []} Use null for any value the message does not give. Put anything the customer asked about in "questions" as short strings. Message: [paste the customer message here] [/ita_prompt]

An example object works better than a description of the fields. It shows the key names, which values are numbers, and how dates are written.

Your code should still check the result before using it. Parse it, confirm every key is there, and handle the failure case. The article on system prompts and structured output for builders goes further into this.

[ita_why title="Why does a chatbot sometimes break JSON?"]

A model writes JSON the same way it writes a sentence: one piece of text at a time, predicting what comes next. Nothing checks that every bracket closes, unless the app or the code around the model adds that check.

Three failures are common. The model adds a friendly sentence before the JSON, it renames a key, or a long answer reaches the output limit and stops halfway. A short example object and the line "no text before or after it" make the first two less likely. Only your code can catch all three.

Try it

Design the table on paper before you ask for it.

  1. Pick one real job that ends in a list: a delivery round, a stock count, or prices from three suppliers.
  2. On paper, write the column names across the top, in the order you want them.
  3. Fill one row by hand, so you know what a good row looks like.
  4. Turn the paper into a prompt: columns, order, sorting, the word for missing values, and your hand-filled row as an example.
  5. Paste the result into your spreadsheet. Where a column lands in the wrong place, fix that line of the prompt and save it.
