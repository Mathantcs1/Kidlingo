Can you run a language model on your own laptop or desktop? Often, yes. Smaller open-weight models can run on ordinary computers, and faster with a recent graphics card or plenty of memory. What you get depends on the model's size and on your hardware.

Expect a trade: more privacy and control, and usually less speed and capability than large hosted models.

What you need

  • The model files. You need an open-weight model whose license allows your use (see "Open vs closed models"). Many models come in several sizes. Start with a small one.
  • A program that runs them. Several programs load model files and let you chat with the model or call it from code. Many can also offer a local server. It accepts requests in a format similar to common hosted APIs, so your code can switch between local and hosted with small changes.
  • Enough fast memory. For good speed, the whole model usually needs to fit in the graphics card's memory, or in fast main memory on some machines. If it doesn't fit, the program may split the work or refuse to load, and speed can drop sharply.

Download model files only from sources you trust. Some file formats can run code when they're loaded. Prefer formats that store only the numbers.

What to expect

Local models are improving quickly, so test them on your own tasks before deciding anything. Some differences from hosted models are common, though:

  • Speed. Replies often arrive more slowly, and the first request can take longer while the model loads into memory.
  • Quality. Smaller models make more mistakes on hard reasoning, long documents and complex instructions. They're often fine for focused jobs: extracting fields, sorting short messages, rewording text.
  • Context length. Memory use grows with the length of the input. On your machine, the usable context window can be smaller than the model's stated maximum.
  • Extras. Hosted apps add features around the model, such as web search, file reading and safety filters. Locally, you get only what's in the weights and what you add yourself.
  • Your machine. Expect heat, fan noise and battery drain during long runs.

Privacy is the main reason many builders run models locally. Your text stays on your machine as long as the program doesn't send anything out. Check its settings for update checks, usage reports or optional online features.

[ita_why title="How a big model fits into less memory"]

A model's parameters are numbers, and each number takes a certain number of bits to store. [ita_term define="Storing a model's numbers with fewer bits each, so it needs less memory."]Quantization[/ita_term] rounds them so each one uses fewer bits.

The file gets smaller, the model needs less memory, and it often runs faster. The cost is some loss of quality, which grows as fewer bits are used. Many local model files are offered at several quantization levels, so try more than one on your own tasks.

[/ita_why]

Prompting a smaller model

Smaller models follow long, layered instructions less reliably. A [ita_term define="The message or instructions you type to an AI app to tell it what you want."]prompt[/ita_term] for them works better when it gives one job. It should also mark where the input starts and ends, and show the exact output shape:

[ita_prompt title="One job, clear edges"] You extract dates. Do one task only. Task: list every date in the text below and what happens on that date. Output: one line per date, in this form: YYYY-MM-DD | event If the text has no dates, output only: NONE ### TEXT START [paste the text] ### TEXT END [/ita_prompt]

Keep the input short enough to leave room for the reply, and split long documents into parts. If a task needs several steps, send each step as its own request and join the results in your code.

Try it

A quick version, before you download anything:

  1. Write five short test tasks from your real work, such as pulling dates from a note or summarizing a page of documentation. Remove names, and use real text only if your workplace allows it.
  2. Run the five tasks on the hosted model you use now, and mark which answers you would accept.
  3. After you install a local model, run the same five tasks and mark each answer "good enough" or "not good enough".
