An AI agent is a program that uses an AI model to decide what to do next, does it with tools, looks at the result, and repeats until the goal is met (or until it's stopped). A chatbot answers your message and waits. An agent keeps going on its own, one step after another.

Acting in a loop is what makes agents useful, and also what makes them riskier.

The line between chatbots and agents is blurry in practice: many chat apps now have agent-like features, such as searching the web before they answer.

The short definition

Three ingredients make something an agent:

  • A model that decides. A [ita_term define="A program trained on a very large amount of text to predict which piece of text is likely to come next."]language model[/ita_term] reads the goal and what has happened so far, and chooses the next step.
  • Tools. A [ita_term define="A capability the agent's program offers the model, such as searching the web, reading a file or adding a calendar entry."]tool[/ita_term] lets the agent do something besides writing text, for example look something up, read a document or fill out a form.
  • A loop. After each action, the result goes back to the model, which decides whether to take another step or stop.

Without tools, a model can only write text. Without the loop, it can use a tool once and hand back to you. With both, it can work through a task step by step.

The agent is the whole program: the model plus the code that runs its tools.

Chatbot vs agent

Imagine you want to find a free hour for a meeting with two colleagues next week, then send them an invitation.

A plain chatbot can help you think. It can suggest how to word the invitation or remind you to check time zones, while you do the checking and the sending yourself. It only sees what you paste in.

An agent with access to the right tools could do the steps itself: read the three calendars, find hours that are free for everyone, pick one, draft the invitation and send it. You give it a goal, not a list of instructions.

The agent saves you clicks, but it also makes decisions you used to make, and it can get them wrong. Which calendar did it read? Did it understand "next week" the way you meant it? Did it send the invitation before you had a chance to look?

The loop, step by step

[ita_figure name="agent-loop" alt="A goal enters a loop of plan, act, observe and check; the check either goes back to plan or ends with a result." caption="The agent loop: plan, act, observe, check, and repeat until done."]

Most agents follow some version of this cycle:

  1. Plan: the model looks at the goal and everything so far, and picks the next step.
  2. Act: it asks for a tool to be used, such as "search the calendar for free hours on Tuesday".
  3. Observe: the tool's result is added to what the model can see.
  4. Check: the model decides whether the goal is met. If it isn't, it goes around again.

Well-built agents usually have limits the model can't change: a maximum number of steps, a list of allowed tools, and points where a person must approve before anything hard to undo happens.

[ita_why title="Who actually runs the tool?"]

The model itself never clicks a button or opens a file. It only produces text. With [ita_term define="A way for a model to ask the surrounding program to run a named tool with specific inputs, using a fixed, structured format."]tool calling[/ita_term], that text is a structured request containing the name of a tool and the inputs to give it.

The program around the model reads that request, may check it is allowed, runs the tool, and passes the result back as more text. Then the model predicts its next step.

This matters for safety. What an agent can do depends on which tools the program offers and what checks it runs before using them. The model's judgment is only one layer.

[/ita_why]

Where agents go wrong

Agents inherit every weakness of the model inside them, and the loop can make those weaknesses bigger. Four problems come up again and again:

  • Small errors add up. If an early step reads the wrong file, every later step builds on that mistake.
  • The goal gets misread. "Tidy up my downloads folder" could mean sorting files into folders or deleting old ones. A person would ask; an agent may just pick one.
  • Hidden instructions mislead it. An agent that reads web pages or emails can come across text written to look like instructions. Even well-built agents can be fooled by this, which is why limiting their tools and approvals matters.
  • It gets stuck. Without a step limit, an agent can repeat the same failing action over and over.

In practice that means a clear goal, limited permissions, and someone checking the work before anything important goes out. The checklist below turns that into questions you can ask about any agent.

[ita_checklist id="agent-before-acting"] [ita_item]The goal is written in one clear sentence, including what "done" looks like.[/ita_item] [ita_item]The agent can only use the tools this task needs.[/ita_item] [ita_item]Anything hard to undo (sending, paying, deleting) waits for a person to approve it.[/ita_item] [ita_item]There is a limit on how many steps it may take.[/ita_item] [ita_item]You can see a record of what it did, step by step.[/ita_item] [/ita_checklist] [ita_quiz] [ita_q q="What is the main difference between a plain chatbot and an agent?" answers="An agent can take several steps with tools in a loop before handing back to you|An agent always runs on a larger, newer model|A chatbot can never use any outside information" correct="1" why="A chatbot replies and waits; an agent decides on steps, uses tools and repeats until the goal is met or it is stopped."] [ita_q q="With tool calling, who actually runs the tool?" answers="The model itself, while it writes its answer|The person, who copies each request by hand|The program around the model" correct="3" why="The model outputs a structured request; the surrounding program runs the tool and returns the result."] [ita_q q="Which action is the most sensible to put behind a human approval step?" answers="Reading a calendar to find free hours|Sending an email to a client|Summarizing a document you shared" correct="2" why="Sending is hard to undo, so a person should check it first."] [/ita_quiz]

Try it

You don't need any software for this, only paper or a notes app and five minutes.

  1. Pick a small errand you do often, such as booking a haircut or planning the weekly grocery shopping.
  2. Write the goal in one sentence, including what "done" looks like.
  3. List the tools an agent would need: which apps or information would it have to read or change?
  4. Write the steps of the loop: what would it plan, do, observe and check each time around?
  5. Circle every step that would be hard to undo. Those are the ones you'd want to approve yourself.

Keep the page; you can use it to judge any agent you try later. If you can't write the goal and the approval points clearly, the task isn't ready to hand to an agent yet.
