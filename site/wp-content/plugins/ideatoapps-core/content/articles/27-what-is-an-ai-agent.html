An AI agent is a program that uses an AI model to decide what to do next, does it with tools, looks at the result, and repeats until the goal is met. A chatbot answers your message and waits. An agent keeps going on its own, one step after another.

That small difference, acting in a loop instead of replying once, is what makes agents useful. It's also what makes them riskier.

The short definition

Three ingredients make something an agent:

  • A model that decides. A [ita_term define="A program trained on a very large amount of text to predict which piece of text is likely to come next."]language model[/ita_term] reads the goal and what has happened so far, and chooses the next step.
  • Tools. A [ita_term define="A capability the agent's program offers the model, such as searching the web, reading a file or adding a calendar entry."]tool[/ita_term] lets the agent do something besides writing text: look something up, read a document, run a calculation, fill in a form.
  • A loop. After each action, the result goes back to the model, which decides whether to take another step or stop.

Take away the tools and you have a chatbot. Take away the loop and you have a chatbot that can use one tool once. Put all three together and you have an agent.

Chatbot vs agent

Imagine you want to find a free hour for a meeting with two colleagues next week, then send them an invitation.

A chatbot can help you think. It can suggest how to word the invitation or remind you to check time zones. But you do the checking and the sending. It only sees what you paste in.

An agent with access to the right tools could do the steps itself: read the three calendars, find hours that are free for everyone, pick one, draft the invitation, and send it. You give it a goal, not a list of instructions.

That's the trade. The agent saves you clicks, but it also makes decisions you used to make, and it can make them wrongly. Which calendar did it read? Did it understand "next week" the way you meant it? Did it send the invitation before you had a chance to look?

The loop, step by step

[ita_figure name="agent-loop" alt="A goal enters a loop of plan, act, observe and check; the check either goes back to plan or ends with a result." caption="The agent loop: plan, act, observe, check, and repeat until done."]

Most agents follow some version of this cycle:

  1. Plan: the model looks at the goal and everything so far, and picks the next step.
  2. Act: it asks for a tool to be used, such as "search the calendar for free hours on Tuesday".
  3. Observe: the tool's result is added to what the model can see.
  4. Check: the model decides whether the goal is met. If not, it goes round again.

Well-built agents also have limits the model can't change: a maximum number of steps, a list of allowed tools, and points where a person must approve before anything happens.

[ita_why title="Who actually runs the tool?"]

The model itself never clicks a button or opens a file. It only produces text. With [ita_term define="A way for a model to ask the surrounding program to run a named tool with specific inputs, using a fixed, structured format."]tool calling[/ita_term], that text is a structured request: the name of a tool and the inputs to give it.

The program around the model reads that request, checks it is allowed, runs the tool, and passes the result back as more text. Then the model predicts its next step.

This matters for safety. Everything an agent can do is decided by which tools the program offers and what checks it runs before using them. The model's judgement is only one layer.

[/ita_why]

Where agents go wrong

Agents inherit every weakness of the model inside them, and the loop can make those weaknesses bigger.

Small errors add up. If an early step gets something wrong, such as reading the wrong file, every later step builds on that mistake.

They can misread the goal. "Tidy up my downloads folder" could mean sorting files into folders, or deleting old ones. A person would ask. An agent may just pick one.

They can be misled. An agent that reads web pages or emails can come across text that looks like instructions. A careless setup might follow them.

They can get stuck. Without a step limit, an agent can repeat the same failing action over and over.

None of this means agents are useless. It means they need the same thing a new assistant would: a clear goal, limited permissions, and someone checking the work before anything important goes out.

Try it

You don't need any software for this. You need paper, or a notes app, and five minutes.

  1. Pick a small errand you do often, such as booking a haircut or planning a weekly shop.
  2. Write the goal in one sentence, including what "done" looks like.
  3. List the tools an agent would need: which apps or information would it have to read or change?
  4. Write the steps of the loop: what would it plan, do, observe and check each time round?
  5. Circle every step that would be hard to undo. Those are the ones you'd want to approve yourself.

Keep the page. It's a good test for any agent you try later: if you can't write the goal and the approval points clearly, the agent can't either.
