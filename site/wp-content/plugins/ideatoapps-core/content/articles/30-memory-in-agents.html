A common mistake is to expect an agent to remember yesterday's work by itself. The model inside it keeps nothing between requests. Anything an agent "remembers" is text that your code saved and then added to a later request.

Two kinds of memory

[ita_figure name="agent-memory" alt="An agent reads from and writes to short-term memory, the current chat, and long-term memory, saved notes it can find later." caption="Short-term memory is the current chat; long-term memory is saved notes, found when needed."]

Short-term memory is what's in the context window right now: the instructions, the conversation, tool results and any notes added for this task. It's limited by the window's size, as "Context windows" explains.

Long-term memory is stored outside the model, in a file or a database. Your code finds the notes that matter and adds them to the window. Chat apps with a memory feature work the same way: saved notes are added to later chats.

Builders often store three kinds of long-term notes:

  • Facts about the user, such as their courses or preferred language.
  • Records of past tasks: what was tried, what worked and what failed.
  • Working rules the user has stated, such as "always show times in 24-hour format".

Short notes are usually added to every request. Larger collections are often searched, the same way RAG searches documents, and only the closest matches are added.

Deciding what to save

Say you're building a study helper agent for university students. It could save a lot: courses, exam dates, topics a student struggled with, and small remarks. Most of that shouldn't become permanent.

A useful rule: the model suggests notes, and your code decides what is stored. Save only stable facts the user stated or confirmed, with a date and a source. Skip guesses about the user. Never save passwords or ID numbers. Store sensitive personal details only if the user clearly agreed. Give users a way to see and delete what's stored about them.

You can ask the model to draft the notes at the end of a session with a [ita_term define="The message or instructions you type to an AI app to tell it what you want."]prompt[/ita_term] like this:

[ita_prompt title="Memory-write rule"] Review this session and suggest notes to save for future sessions. Suggest a note only if the user stated or confirmed it, and it is likely to stay true for weeks. Write each note on one line, in this form: [date] | [fact] | source: user said / user confirmed Do not suggest guesses about the user, passwords, ID numbers, health details or anything the user asked you to forget. If nothing qualifies, reply: NO NEW NOTES Session: [session text] [/ita_prompt]

Before storing anything, check each line in code: the format, the source field, and a check for passwords, ID numbers and other blocked data.

Reading memory back

Old notes can cause new mistakes. Plan for these:

  • Stale notes. An exam moves, a course is dropped. Prefer the newest note, and let notes expire.
  • Wrong notes that repeat. A note saved by mistake is added to every later session until someone removes it.
  • Notes from the wrong person. Keep each user's memory separate, and filter by user before searching.
  • Planted instructions. Text an agent saved from a web page or email can contain instructions. Once stored, they can affect later sessions.
  • Too many notes. Every note takes space in the window. Cap how many are added per request.
[ita_why title="Memory is more text in the window"]

To the model, a memory note is just text. Unless your code labels it, the model can't tell a note from a message the user typed just now.

Label notes clearly, with their date and source, so the model can judge their age. When a note and a new message disagree, the model needs a rule. Tell it in its instructions to prefer the newer message. Then ask the user before the note is updated.

Try it

Use a sheet of paper for this one; no app is needed.

  1. Write the job of one agent you build or plan, in one line.
  2. List everything it might want to remember between sessions.
  3. Next to each item, write who confirms it, when it expires and who can see it.
  4. Draw a line through every item where you can't answer all three. Turn the rest into the fields of your memory note.
