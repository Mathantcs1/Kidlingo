Ask a chatbot for a title for a video about fixing a bike chain. If your app has a button that writes the answer again, press it. You'll usually get a different title, because each word is picked with some randomness, and a setting called [ita_term define="A setting that controls how much randomness goes into picking each next piece of text."]temperature[/ita_term] controls how much.

What the setting changes

As "What AI is and isn't" explains, a model writes one piece of text (a token) at a time. At each step it gives every possible next token a likelihood, and the app picks one. Temperature changes how that pick is made.

  • Low temperature: the most likely tokens get an even bigger share, so the pick is nearly always the top choice. Answers vary less between runs.
  • High temperature: the likelihoods are evened out, so less likely tokens are picked more often. Answers vary more, and word choices get more unusual.

Some APIs offer a second control called [ita_term define="A setting that limits the pick to the most likely tokens whose likelihoods add up to a chosen share."]top-p[/ita_term]. With it, the app picks only from the smallest group of top tokens whose likelihoods add up to the number you set. A lower top-p removes the unlikely tokens from the choice.

Scales, defaults and names differ between providers, so check the documentation for the one you use.

Lower is steadier, not more correct

Many people believe that a temperature of zero makes a model accurate. It makes the model more consistent. If the most likely answer is wrong, a low setting gives you the same wrong answer every time.

Even at the lowest setting, two runs can differ slightly, because of how the computing is split up on the servers. Some APIs accept a [ita_term define="A number that fixes the random choices, so the same request is more likely to give the same result."]seed[/ita_term] for more repeatable results. Don't build anything that needs identical text on every run.

High settings have a cost too. At very high values, text can lose the topic or stop making sense.

Choosing a setting for each task

For builders, the right setting depends on what a good answer looks like. These are starting points to test:

  • Pulling fields out of text, such as dates and order numbers from delivery notes: low. You want the same answer every time.
  • Answers about a document you send: low to middle. The wording can vary; the facts shouldn't.
  • Drafts of emails, scripts or product text: the provider's default is a fair start.
  • Brainstorming names, titles or angles: higher. Variety is the goal, so read the results for nonsense.

Test each task by sending the same input several times and reading the spread of answers. One run tells you little about a random process. Some models and APIs fix the temperature or ignore changes to it, so check that the setting has an effect before you tune it.

[ita_why title="What the temperature number changes"]

For each possible next token, the model produces a raw score. Before the pick, the app divides every score by the temperature. Then it turns the results into likelihoods that add up to one.

Dividing by a number below one stretches the gaps between scores, so the top token wins even more often. Dividing by a number above one shrinks the gaps, so the choices become more even. At zero, systems usually skip the division and take the top token.

[/ita_why]

When your app has no temperature control

Most chat apps choose the temperature for you and don't show it. Creators can still get more varied answers through the [ita_term define="The message or instructions you type to an AI app to tell it what you want."]prompt[/ita_term] itself.

Ask for several options in one reply, and name how they should differ. The model sees its earlier options while it writes the next one, which usually moves it away from repeats.

[ita_prompt title="Different on purpose"] Write [number] titles for [your content, for example: a short video about fixing a bike chain] (example values: replace them). Make each title differ from the others in one way: [first way, for example: tone], [second way, for example: length], [third way, for example: whether it asks a question]. Number the titles. After each one, add a two-word label for what makes it different. [/ita_prompt]

For a steady result across many posts, reuse the same request word for word and change only the facts each time.

Try it

  1. Pick one task you repeat, such as writing video titles or pulling dates out of messages. If you use real messages, remove names, and paste them only if your workplace allows it.
  2. Send the same request three times, using the button that writes the answer again or three new chats. Put the three answers side by side.
  3. Mark what changed in each: only the wording, the structure, or a fact or number.
  4. If a fact or number changed, lower the temperature in your code or add that fact to the request. Then run it three more times.
