If you've ever asked a chatbot for a video title and then pressed the button that writes the answer again, you've seen the title change. Each word is picked with some randomness, and a setting called [ita_term define="A setting that controls how much randomness goes into picking each next piece of text."]temperature[/ita_term] controls how much.

How the pick works

"What AI is and isn't" shows how a model writes one piece of text (a token) at a time. At each step it gives every possible next token a likelihood, and the software running the model picks one. Temperature changes how spread out that pick is.

At a low temperature, the likely tokens get an even bigger share. The pick is nearly always the top choice, so answers vary less between runs. At a high temperature, the likelihoods are evened out. Less likely tokens are picked more often, so answers vary more and the wording gets more unusual.

If you send requests from your own code through an [ita_term define="Application programming interface: the connection a program uses to send requests to a model and get answers back."]API[/ita_term], you may see a second control called [ita_term define="A setting that limits the pick to the most likely tokens whose likelihoods add up to a chosen share."]top-p[/ita_term]. With it, the pick is made only from the smallest group of top tokens whose likelihoods add up to the number you set. A lower top-p removes the unlikely tokens from the choice. Each provider sets its own range and default for both controls, and some models ignore them.

[ita_why title="What the temperature number changes"]

For each possible next token, the model produces a raw score. Before the pick, the software divides every score by the temperature. Then it turns the results into likelihoods that add up to one.

Dividing by a number below one stretches the gaps between scores, so the top token wins even more often. Dividing by a number above one shrinks the gaps, so the choices become more even. At zero, systems usually skip the division and take the top token.

[/ita_why]

Three beliefs about temperature

"Zero makes the answers accurate"

A low setting makes a model more consistent, which can feel like accuracy. But if the most likely answer is wrong, a low temperature gives you the same wrong answer every time.

"The same setting always gives the same text"

Even at the lowest setting, two runs can differ slightly. Part of the reason is how the servers group and calculate many requests at once. Some APIs accept a [ita_term define="A number that fixes the random choices, so the same request is more likely to give the same result."]seed[/ita_term] for more repeatable results, but nothing you build should depend on identical text every time.

"Higher means more creative work"

A higher setting gives more unusual word choices, which is different from better ideas. At very high values, text can lose the topic or stop making sense.

Picking a setting for a task

The right setting depends on what a good answer looks like. If your code pulls dates and order numbers out of delivery notes, you want the same answer every time, so start low. Answers about a document you send can use a low to middle setting: the wording may vary, but the facts shouldn't.

Drafts of emails and scripts usually do fine at the provider's default; change it only if every draft starts to sound alike. Brainstorming names or angles is where a higher setting helps, as long as someone reads the results for nonsense.

Whatever you choose, send the same input several times and read the spread of answers. A single run can look right by luck, and a setting that seems fine once may change a number on the fourth try.

Variety without a temperature control

Most chat apps choose the temperature for you and don't show it. You can still steer how varied the answers are through the [ita_term define="The message or instructions you type to an AI app to tell it what you want."]prompt[/ita_term] itself.

Think of a retired woodworker who posts short videos from his workshop and wants ten captions that really differ. You've probably noticed that pressing the button again often gives near-copies. Asking for all ten in one reply, with a named way for each to differ, works better. The model sees its earlier options while it writes the next one, which usually moves it away from repeats. Try it

  1. Pick one task you repeat, such as writing video captions or pulling dates out of messages. If you use real messages, remove names, and paste them only if your workplace allows it.
  2. Send the same request three times, using the button that writes the answer again or three new chats. Put the three answers side by side.
  3. Mark what changed in each: only the wording, the structure, or a fact or number.
  4. If a fact or number changed, lower the temperature in your code or the app settings, and compare each number with the original text. Then run it three more times.
